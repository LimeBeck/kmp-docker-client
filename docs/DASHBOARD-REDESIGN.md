# План редизайна dashboard

Статус: реализовано в sample; см. результаты проверки ниже. Дата: 2026-09-15.

## Цель

Сделать dashboard аккуратным ежедневным инструментом для одного Docker host: быстро найти контейнер, понять его состояние, открыть логи/терминал и безопасно изменить ресурсы. Редизайн охватывает визуальный язык, компоновку и обратную связь, а не только смену цветов.

Основание: дизайн-ревью исходников. Живой браузер был недоступен; точные размеры, контраст и поведение существующего интерфейса требуют проверки при реализации. Концепт использует демонстрационные данные.

Контракты:
- spec://io.github.limebeck.kmp-docker-client/specs/ipc/FEAT-002.md#boundary — development example, один host; без добавления Compose, multi-host, ролей и авторизации.
- spec://io.github.limebeck.kmp-docker-client/specs/ipc/FEAT-002.md#acceptance — UI-проверки относятся к sample, не становятся gates релиза SDK.
- spec://io.github.limebeck.kmp-docker-client/specs/ipc/PROP-001.md#exec.dashboard-sizing — сохранить resize, fullscreen/Escape, переключение alternate buffer и освобождение ресурсов.
- spec://io.github.limebeck.kmp-docker-client/specs/ipc/PROP-000.md#samples.dashboard — сохранить loopback binding.

## Визуальное направление

Спокойный инженерный интерфейс: графитовая тёмная тема, согласованная светлая тема, один синий акцент, тонкие разделители и минимум теней. Нейтральные заголовки, монохромные иконки вместо emoji. Названия ресурсов важнее ID; monospace только для технических значений и терминала.

- Сетка отступов: 4/8/12/16/24/32 px; радиусы 8–12 px.
- Основной текст 14–16 px, вторичный 12–13 px, заголовок страницы 26–30 px. Табличные числа выравнивать и форматировать единообразно.
- Один главный CTA на экран. Вторичные действия нейтральные. Красный — ошибка или разрушительное действие, не обычная остановка.
- Статусы: running — зелёный; stopped/created — нейтральный; paused/restarting — предупреждение; ошибка — красный. Всегда текст рядом с цветом. Running не означает application readiness; причину ошибки выводить только из доступных данных.
- Desktop: узкая боковая навигация, небольшой контекст host, свободная основная область. Mobile: компактная верхняя навигация, перенос действий; таблица имеет собственную прокрутку при необходимости.
- Собрать общие токены и компоненты; исключить случайные цвета/отступы в отдельных Kotlin-шаблонах. Сохранить Ktor + kotlinx.html + HTMX + xterm; смена frontend-стека не требуется.

## Экраны

### Containers

Заголовок и Create container → краткие счётчики состояний → поиск по имени/ID/image и фильтр состояния → таблица. Список становится главным содержимым. Поля таблицы: Name (ID вторичной строкой), Image, State, Actions. Название — ссылка на детали; разрушительные действия вынести в меню. Сортировка по имени и состоянию; поиск/фильтр сохранять в URL и при возврате. На первой итерации поиск по загруженному списку, без нового backend поиска и пагинации.

### Container details

Breadcrumb → имя, статус и image → основные действия → Overview / Logs / Terminal / Configuration. Overview показывает существующие данные: порты, mounts, последнее значение памяти в MiB/GiB и время обновления. Не добавлять выдуманные CPU-графики и историю метрик. Детали доступны по прямой ссылке; вкладки совместимы с back/forward.

Логи доступны после остановки: конечная выборка для stopped и live tail для running. Follow включён, пока пользователь у конца ленты; ручная прокрутка вверх отключает следование. Кнопки Follow и Reconnect; отдельные состояния connecting/live/ended/disconnected. Обновлять только поток, не всю страницу. Объяснить ограничение последних 200 записей, отсутствие replay и возможный разрыв при reconnect.

Терминал получает явный статус соединения и команду открытия с подписью. Повторное открытие означает новую exec-сессию, не восстановление старой. Сохранить существующие fullscreen/resize/cleanup гарантии.

### Create / Recreate

Отдельная страница формы с Cancel/Back. Секции: Basics, Environment, Ports, Volumes, Network; расширенные параметры раскрываются по запросу. Для env/ports/volumes — подписанные строки с добавлением/удалением и примерами формата. Сохранить точность аргументов команды; пустая команда использует image default. Явно объяснить текущие defaults, включая TTY; их изменение выполнять отдельным согласованным изменением поведения.

Значения сохраняются при ошибке. Валидация рядом с полем, общая ошибка над формой; disabled/loading защищает от повторной отправки. При отсутствии image дать переход к Pull с сохранением draft. Не переносить env/секреты в URL или browser storage; draft хранить только в памяти текущей страницы, очищать после завершения.

Recreate сохраняет ограничение sample-managed и существующий сценарий prepare → verify → confirm/rollback. Показывать старый и новый контейнер, последствия действий и предупреждение о shared-volume writes.

### Images / Volumes / Networks / System

Применить общую структуру списка, поиска, empty/error/loading и меню действий. Images: Pull открывается отдельно, прогресс и итог выделены; Cancel доступен только при активной операции; после завершения предложить обновить список. Volumes: показывать имя и driver прежде технического mountpoint; подтверждать Delete/Prune и отображать ошибки API. Networks остаётся просмотром существующих данных, без новых CRUD-сценариев. System: аккуратные группы host/engine и подписанная лента событий, без декоративных KPI.

## Общие UX-состояния

- Empty: «No containers yet» и Create; no results: «No matches» и сброс фильтров. Ошибка загрузки не маскируется под пустой список.
- Loading: индикатор рядом с операцией, блокировка повторного запроса, aria-busy; существующие данные остаются до ответа.
- Error: понятное действие для восстановления, сохранённый контекст, role=alert; закрытие только отдельной доступной кнопкой.
- Delete: диалог с именем, областью удаления и последствиями; для контейнера явно указать сохранение named volumes и принудительную остановку, если применяется force.
- Prune: объяснить реальную семантику текущего API-вызова; не обещать точный preview или количество объектов, если они неизвестны. Для удаления данных volume — явное подтверждение имени; для prune отдельное подтверждение области.
- Keyboard: настоящие ссылки, активный раздел aria-current, видимый focus, подписи полей, возврат фокуса после диалога, Escape. После HTMX-навигации обновлять title и переносить фокус к заголовку.

## Порядок реализации

Каждый шаг — отдельный атомарный commit с проверкой и WAL update. Существующее поведение и новые UX-контракты документировать явно; не переписывать нормативные значения молча.

1. **Foundation и shell.** Токены тем, типографика, навигация, buttons/fields/status/notice/dialog/table. Применить shell ко всем разделам. Результат: единый визуальный язык без поломки текущих ссылок.
2. **Containers list.** Перенести создание на отдельный маршрут, добавить поиск/фильтры/сортировку и состояния списка. Результат: основной экран посвящён управлению существующими контейнерами.
3. **Delete/Prune и feedback.** Подтверждения, обработка результатов volume операций, busy/error/success, предотвращение повторных отправок. Результат: последствия понятны до запроса, исход виден после.
4. **Формы create/recreate.** Секции, field errors, сохранение draft, доступные контролы и состояние replacement. Результат: ошибку можно исправить без повторного ввода конфигурации.
5. **Details и streams.** Вкладки, логи stopped, follow/reconnect, форматирование памяти, статус terminal. Результат: диагностика доступна после сбоя, чтение истории не прерывается автоскроллом.
6. **Остальные разделы.** Перенести Images/Volumes/Networks/System на компоненты, привести Pull и события к общей системе состояний.
7. **Полировка и приёмка.** Темы, длинные данные, адаптивность, keyboard, browser back/forward, потоки и fullscreen. Обновить docs/DASHBOARD.md и приложить реальные screenshots результатов.

Основные точки изменений: ui/components.kt, ui/liveStream.kt, ui/terminal.kt; routes/containers/{components,route,lifecycle}.kt; routes/images/{components,pullForm,route}.kt; routes/volumes/{components,route}.kt; компоненты Networks/System и Utils для навигации/ошибок. При необходимости вынести общие стили и небольшой JS в локальные assets, согласованно упакованные в Native executable.

## Критерии готовности

- На 375/768/1280 px страница не имеет общего горизонтального скролла, обрезанных действий и перекрытий. На 320 px доступен базовый сценарий. Проверить 200% zoom.
- Проверить светлую и тёмную темы, видимый focus и контраст текста/контролов; действия не зависят только от цвета или hover.
- Состояния данных: 0/1/50 контейнеров, длинные имена/теги/пути, missing values, stopped/error/loading/disconnected и ошибка Docker.
- Поиск, фильтры, сортировка, прямые ссылки, refresh и back/forward не теряют ожидаемый контекст; семантика ссылки работает с клавиатурой и открытием в новой вкладке.
- Ошибка формы сохраняет значения; повторный клик не дублирует запрос; Delete/Prune требуют контекстного подтверждения; ошибка API видна.
- Логи stopped читаются. Ручная прокрутка не сбрасывается. Reconnect не создаёт параллельных подписок; выход из вкладки закрывает поток.
- Terminal: shell и alternate buffer, fullscreen и fallback, Escape, изменение размеров, отключение и уход со страницы без утечек слушателей/сессий.
- Compile/check релевантного sample и git diff --check. Для изменений routes/streams — адресные проверки сценариев, без snapshot-тестов каждой косметической детали.
- Проверки разрушительных операций только на выделенных disposable ресурсах/отдельном daemon; не перезапускать рабочий dashboard или host daemon ради ревью.

## Результат реализации

- По замечанию владельца мобильная компоновка переработана: до 640 px таблицы становятся карточками, данные и действия видны без горизонтальной прокрутки; навигация помещается в одну строку, фильтр и сортировка стоят рядом.
- Проверены ширины 320/375/768/1280 px без горизонтального переполнения страницы. На планшете устранено растягивание шапки при коротком списке.
- Общий shell и компоненты применены ко всем разделам. Переключатель темы — кнопка солнце/луна по уточнению владельца.
- Список, вкладки деталей, отдельная форма, повторяемые поля, подтверждения удаления, ошибки и состояния потоков реализованы.
- Embedded Pull сохраняет форму в памяти текущей страницы; секреты не помещаются в URL или history cache. Cancel не наследует параметры POST-формы.
- Backend библиотеки, её версия и release pipeline не изменены. Новые файлы тестов относятся только к sample.
- Native debug executable собран с warning-as-error. Семь DOM-тестов и 28 HTTP smoke-проверок прошли; HTTP-проверки выполнили create/start/stop, логи stopped, ошибку формы, prepare/rollback/confirm и сохранение named volume. Одноразовые ресурсы убраны.
- Во встроенном браузере проверены реальные списки (47 контейнеров, 109 images), темы, форма с ошибкой, создание разрешённого одноразового контейнера, вкладки и терминал. Подтверждены вывод команды, resize с 26×106 до 43×136 в fullscreen, Escape и alternate-buffer scrollbar. Контейнер проверки терминала удалён.
- UI-инспекция обнаружила и устранила наследование HTMX swap/select у Cancel, отправку параметров формы при GET и устаревший обработчик ссылки возврата к фильтру.
- Browser fullscreen fallback при отказе API и точный zoom 200% отдельно не форсировались. Существующая логика fallback сохранена. Реальный daemon restart и SDK release gates не входят в эту UI-проверку.
